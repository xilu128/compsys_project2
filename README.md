# COMPSYS704 Project 2 — Group 02

SensorTile step counting, distance estimation and gyro-aided horizontal heading.
Current firmware: **heading-handheld-10**. Start with [SUBMISSION.md](SUBMISSION.md)
for Windows setup, import, build, test and submission instructions.

## Current behaviour

- Heading is relative to the accepted startup direction, not geographic north.
  Clockwise 90° displays 90; counterclockwise 90° displays 270. Whole-degree
  output is 0–359, and full turns return to zero.
- Startup needs a two-second gyro window followed by three one-second magnetic
  windows. Bounded hand tremor is accepted; persistent turning, stale samples
  and changing magnetic conditions can extend initialization.
- Recovery needs two seconds and at least 80 fresh magnetic samples. It retains
  the startup zero, gyro bias and step count. It does not force an invalid zero.
- Gyro prediction with selective accelerometer and magnetic corrections
  compensates for moderate tilt. Heading is poorly defined when board +X is
  nearly vertical. This is not a full three-axis attitude display.
- Step detection uses adaptive peak/trough checks, walking-bout confirmation
  with initial-step backfill, and repeated-handling rejection. Distance uses
  an assumed 0.70 m step length.

## Verification and limits

See [VALIDATION.md](VALIDATION.md) for current results and historical evidence.
The current Debug firmware was built and flashed with verification. Default
host regressions and four recorded replays passed. Forty-eight synthetic
handheld cases completed startup by 5.020 s and recovery by 2.000 s; subsequent
120-second stationary deviation peaked at 0.7324°. One board boot first reported
valid heading at 5.201 s, and the operator accepted handheld operation
qualitatively. These are different evidence types, not a guaranteed timing or
accuracy specification.

A separate extreme-boundary diagnostic still exceeds ±5° in four of six cases
(maximum 5.1999°). Magnetic calibration, carrying-position coverage, distance,
battery-only interview operation and actual marking-app interoperability need
further validation. Step detection cannot distinguish every handling motion
from walking.

## Desktop tools

Python 3 with Tkinter is needed for the viewer. Install optional dependencies:

```powershell
python -m pip install -r tools/requirements.txt
python tools/ble_monitor.py
python tools/capture_log.py --name walk_100_normal_01
```

BLE name: P202S01. UART: 115200 8N1. Choose the ST-LINK Virtual COM Port, not a
Bluetooth serial port. Keep only one serial capture process per port. Stop
capture with Ctrl+C; its CSV and raw log paths are printed when recording starts.
